# 法隐 LegalRedactor 设计说明

中文法律文书本地脱敏工具。纯本地、零成本、无需 GPU 大模型。

---

## 1. 为什么做这个，和参考项目的差异

参考项目 [DataInfra-RedactionEverything](https://github.com/ttttccxxui/DataInfra-RedactionEverything)
（原名 TracyWang95/legal-redaction）是一套很完整的企业级脱敏工作台：
Schema 驱动、行业预设、文本链路（PP-StructureV3 OCR + HaS_Text 0.6B 语义 NER）、
视觉链路（LocateAnything-3B 定位人脸/印章/签字 + OpenCV 骑缝章补全）、人工复核、
批量任务、多租户、JWT 鉴权。

它值得借鉴的是**设计骨架**，不适合直接跑的是**资源与授权**：

| 维度 | 参考项目 | 本工具 |
|---|---|---|
| 推理栈 | vLLM + HaS_Text 0.6B + LocateAnything-3B + PaddleOCR，推荐 16GB 显存 | 规则 + 词典 + cv2 + RapidOCR(ONNX CPU)，8GB 显存的笔记本也能跑，实际不吃 GPU |
| 服务拓扑 | 6 个常驻服务、8 个端口、React+FastAPI+SQLite+Docker | 单进程 CLI + stdlib http.server 复核页，零端口依赖 |
| 授权 | 个人非商业免费；LocateAnything-3B 是 NVIDIA 非商用，PyMuPDF 是 AGPL | 全栈规避非商用权重；PyMuPDF 为可选后端，默认走 pypdfium2 兜底 |
| 实体识别 | 语义 NER 为主，正则仅作兜底 | 规则/词典为主，语义为可选插件（留 OpenAI 兼容接口，可接本地模型） |

差异化的核心不在"识别得多准"，而在**脱敏到底干不干净**。

## 2. 威胁模型：什么算泄露

法律文书脱敏的常见失败模式，本工具逐条对抗：

| 编号 | 泄露路径 | 现实后果 | 本工具对策 |
|---|---|---|---|
| L1 | Word 里用黑色矩形/黑底文字盖住 | 选中复制即可还原，`document.xml` 里原文完好 | 真删除：从 XML 中移除字符，不是视觉遮盖 |
| L2 | 只改了正文，页眉页脚/脚注/尾注/批注没改 | 页脚常有当事人姓名、案号 | DOCX 全部件遍历（见 §6 清单） |
| L3 | 修订历史留着原文 | `w:del` 里就是被"删掉"的敏感内容 | 接受所有修订并清除 `w:ins`/`w:del` |
| L4 | 文档属性泄露 | `docProps/core.xml` 的 author/lastModifiedBy 就是承办人真名 | 清空元数据 |
| L5 | PDF 画黑框 | 文本层还在，Ctrl+F 搜得到，复制粘贴出原文 | `add_redact_annot` + `apply_redactions`，或删除文本层后栅格化 |
| L6 | 同一人前后被替换成不同假名 | 文书逻辑断裂，读者能靠矛盾反推身份 | 全局实体解析 + 一致化映射 |
| L7 | 部分残留 | 身份证打了前 12 位留后 6 位，出生日期+地区码足以定位人 | 残留自检做**子串级**扫描，不只全值匹配 |
| L8 | 准标识符组合重识别 | 姓名删了，但"1987年3月生，住某村，独子"仍能定位 | 提供泛化策略（日期→年份、地址→区县级、金额→区间）+ 组合风险提示 |
| L9 | 图片里的红章/签名/二维码 | 印章上有法院或公司全名，二维码一扫就是原始链接 | cv2 HSV 红章检测 + QR 检测 + OCR 定位打码 |
| L10 | 对照表本身泄露 | 脱敏做完把 mapping 表一起发出去，等于没脱 | 对照表 AES-GCM 加密，口令派生密钥，且默认与产物分离存放 |
| L11 | Word 缩略图 | `docProps/thumbnail.jpeg` 是首页位图快照，页眉页脚里的当事人姓名和电话都在里面 | 删除该部件 + 删除 `_rels/.rels` 关系 + 删除 `[Content_Types].xml` 的 Override |
| L12 | 保留类实体吃掉脱敏类实体 | 页眉"…号　**张伟民**诉北京华远置业有限公司"里 ORG 向前回溯把姓名一起吃进机构名，而机构名在 legal 预设下是保留的 → 姓名原样留在产物里 | 通用原则：重叠消解时**保留类实体永远让位给脱敏类实体**（`merge_spans(deprioritize=…)`），不靠补停止词打补丁 |
| L13 | 表格里的裸姓名 | Excel 一格一个"张伟民"，没有角色词、没有"男，1987年"，任何基于上下文的规则都会漏 | 列头驱动检测：列头写"姓名"就是决定性证据（`TabularDetector`） |
| L14 | PDF 换行切断实体 | `page.get_text()` 在换行处插 `\n`，把"北京市朝阳区建国路88号院3号楼2单元401室"从中间切开，后半截永远检不出来 | 用 `rawdict` 做字符级投影，排版换行不投影成字符，靠中文标点断句 |
| L15 | 人工放行与工具失误混为一谈 | 复核人有意保留某项，自检就永远 FAIL，久了大家开始无视 FAIL | 放行项单列成"人工放行清单"，不计入通过/不通过判定，但报告里必须看得见 |

L11、L12 是开发过程中被验证环节真实抓出来的，不是事前想到的。
L12 由第三方独立验证（真实 Word COM）发现，工具自身的 zip 审计当时报了 0 残留——
因为该地址从未被检出、也就从未进对照表，审计无从核对。
这说明**只用自己的提取路径验证自己的产物是不够的**。

## 3. 实体体系

分四层。每层可单独开关，行业预设是这些开关的组合。

### 3.1 强标识符（正则可判定，高置信）

| 类型 | 判定 | 备注 |
|---|---|---|
| `ID_CARD` 居民身份证 | 18 位 + GB11643 校验位 | 校验不通过降级为 `SUSPECT_ID`，避免误杀 |
| `PHONE` 手机号 | `1[3-9]\d{9}` + 号段白名单 | 带 `+86`/分隔符变体归一 |
| `TEL` 固定电话 | 区号-号码 | 3/4 位区号表 |
| `BANK_CARD` 银行卡号 | 13–19 位 + Luhn | 排除已识别为身份证的串 |
| `USCC` 统一社会信用代码 | 18 位 + GB32100 校验 | 企业标识，法律预设默认可保留 |
| `EMAIL` 邮箱 | RFC 简化式 | |
| `IP_ADDR` IPv4 | 点分十进制 + 范围校验 | 排除版本号误报（前后有"版本/v"则跳过）|
| `PLATE` 车牌 | 省份简称+发牌机关代号+5/6 位 | 含新能源 8 位 |
| `PASSPORT` 护照 | `E/G/D/S/P/H/M`\d{8} | |
| `HK_MO_PERMIT` 港澳通行证 | `C/W`\d{8} | |
| `IM_ACCOUNT` QQ/微信 | 触发词 + 数字/字母串 | QQ 号 5–11 位 |
| `URL` 链接 | http(s)/www | 法律预设默认保留裁判文书网链接 |

### 3.2 弱标识符 / 准标识符（需上下文，中置信）

| 类型 | 方法 |
|---|---|
| `PERSON` 自然人姓名 | 三级：① 法律角色触发词（原告/被告/上诉人/被上诉人/申请人/被申请人/被告人/犯罪嫌疑人/证人/鉴定人/审判员/代理审判员/书记员/人民陪审员/法定代表人/委托代理人/辩护人 后接 2–4 字汉字）② 百家姓词典 + 长度 + 非常用词过滤 ③ 文书抬头/落款位置模式 |
| `ADDRESS` 地址 | 级联解析：省/自治区/直辖市 → 市/州 → 区/县 → 镇/乡/街道 → 村/社区 → 路/街/巷 → 号/栋/单元/室；输出行政级别，供泛化策略按级截断 |
| `COURT` 法院名称 | `X人民法院` / `X海事法院` / `X铁路运输法院` 模式 + 法院名录 |
| `LAW_FIRM` 律所 | `X律师事务所` |
| `ORG` 机构/公司 | 后缀驱动：有限公司/股份公司/集团/合作社/事务所/中心/协会/基金会/合伙企业 + 括号内曾用名 |
| `DOB` 出生日期 | `X年X月X日出生` 触发 |
| `DATE` 日期 | 通用日期，法律预设默认保留（裁判文书日期属公开信息）|
| `AMOUNT` 金额 | 阿拉伯数字+元/万元 + 中文大写金额（壹贰叁…元整）|
| `CASE_NO` 案号 | `（2023）京0105民初12345号` 全格式，含涉外/仲裁变体 |

### 3.3 视觉实体（图片/扫描页）

| 类型 | 方法 |
|---|---|
| `SEAL` 印章 | cv2 HSV 红色掩膜 → 形态学 → 轮廓圆度/面积筛选；同时覆盖骑缝章（贴边半圆）|
| `QR_CODE` 二维码/条码 | `cv2.QRCodeDetector` + `cv2.barcode`（若可用）|
| `IMG_TEXT` 图内文字 | RapidOCR ONNX 文本框，框内再做实体检测后打码 |
| `FACE` 人脸 | 可选。默认不启用（需模型权重）；启用时接 OpenCV DNN 或本地 ONNX |

### 3.4 自由裁量项（默认不动，可开）

商业秘密段落、银行账户开户行、财产线索明细、未成年人相关信息
（`未成年`/`X某，2008年出生` → 强制脱敏，法律预设默认**开启**，
因为《最高人民法院关于人民法院在互联网公布裁判文书的规定》第十条
明确要求对未成年人信息做删除处理）。

## 4. 行业预设

| 预设 | 默认脱敏 | 默认保留 |
|---|---|---|
| `legal` 法律（默认） | 自然人姓名、身份证、手机、固话、邮箱、住址、银行卡、车牌、护照、QQ/微信、IP、出生日期、律所、代理人、法官书记员姓名、未成年人信息、印章、二维码 | 案号、法院名、当事人是法人时的名称、金额、日期、法条、URL |
| `legal_public` 裁判文书上网版 | 在 `legal` 基础上追加：当事人住所地泛化到区县级、法定代表人姓名、金额保留但自然人金额泛化 | 法院名、案号 |
| `litigation_internal` 卷宗内部共享 | 只脱联系方式与证件号，保留姓名 | 姓名、地址 |
| `general` 通用 | 姓名、证件、联系方式、地址、账户、车牌、IP、邮箱 | 金额、日期 |
| `finance` 金融 | 通用 + 银行卡、开户行、账号、交易对手、金额泛化 | — |
| `medical` 医疗 | 通用 + 病历号、住院号、就诊日期偏移、社保号 | — |

预设是 YAML，用户可复制改名自定义（`schemas/*.yaml`）。

## 5. 脱敏策略

对每种实体类型可独立指定策略。策略必须保证**同一实体在全批次内映射一致**。

| 策略 | 例 | 适用 |
|---|---|---|
| `MASK` 遮盖 | `张三` → `张某` / `■■` | 姓名（法律行业惯例是"姓+某"）|
| `MASK_FULL` 全遮盖 | `13800138000` → `[已脱敏]` | 证件号、账号 |
| `PARTIAL` 部分保留 | `110105199001011234` → `110105********123X` | 需要保留可核验性时 |
| `PSEUDO` 一致化假名 | `张三` → `李某某`（全局唯一且稳定）| 需要文书可读性 |
| `CODE` 编号化 | `张三` → `当事人A` / `王某1` | 多方主体区分 |
| `GENERALIZE` 泛化 | `北京市朝阳区XX路5号院3号楼2单元401` → `北京市朝阳区` | 地址、日期、金额，抗 L8 组合重识别 |
| `DATE_SHIFT` 日期平移 | 全体日期减 N 天，保持相对间隔 | 医疗、时间序列分析场景 |
| `DELETE` 删除 | 整段移除 | 商业秘密段 |
| `HASH` 假名哈希 | 值 → HMAC 前 8 位 | 需要跨库关联但不想暴露原值 |
| `KEEP` 保留 | — | 显式放行 |

一致性由 `EntityResolver` 保证：
1. 归一化（去空格、全半角、繁简、"某某"后缀）
2. 按 `(类型, 归一化值)` 建索引
3. 同值不同写法（`张三`/`张三某`/`张某`）合并到同一 canonical
4. 冲突检测：若同一假名被两个不同原值占用，自动加序号并告警

## 6. 真删除规范（关键）

### 6.1 DOCX 必须处理的部件清单

```
word/document.xml                    正文
word/header*.xml                     页眉（常有案号、当事人）
word/footer*.xml                     页脚
word/footnotes.xml                   脚注
word/endnotes.xml                    尾注
word/comments.xml                    批注
word/commentsExtended.xml            批注扩展
word/people.xml                      批注作者
word/document.xml 中 w:ins / w:del   修订历史 ← 最易漏
word/embeddings/*.xlsx|*.docx        嵌入对象（OLE）
word/media/*                         图片（走视觉链路）
docProps/core.xml                    author / lastModifiedBy ← 常是承办人真名
docProps/app.xml                     Company / Manager
docProps/custom.xml                  自定义属性
docProps/thumbnail.jpeg              首页缩略图 ← 页眉页脚的敏感信息都在里面
customXml/*.xml                      自定义 XML 部件
```

难点：Word 会把一个实体切到多个 `w:r`/`w:t` 里（拼写检查、格式变化、
`w:proofErr` 都会切分）。做法是**在段落层做"文本投影"**：
1. 把段落所有 `w:t` 拼接成一条逻辑字符串，同时记录每个字符 → `(run_index, char_offset)` 的映射
2. 在逻辑串上跑检测，得到 span
3. 把 span 反投影回各 run，逐 run 改写 `w:t`
4. 若某 run 被清空则整体移除，避免留下空 `w:r` 造成排版异常
5. 改写后重新计算 `xml:space="preserve"`，防止首尾空格被吞

`w:del` 内容：先"接受修订"（把 `w:ins` 内容提升为正常 run，把 `w:del`
整体删除），再走上面的流程。否则被删文本永远留在文件里。

### 6.2 PDF

检测阶段不能直接用 `page.get_text()`：它在换行处插入 `\n`，会把跨行的实体切断
（L14）。做法与 DOCX 同源——**字符级投影**：

1. `page.get_text("rawdict")` 拿到每个字符及其 bbox
2. 按 block → line → span → char 顺序拼成逻辑串，**排版换行不投影成字符**；
   只在句末标点（。；！？：）之后、或下一行以法律角色词开头时才插 `\n`
3. 检测在逻辑串上做，跨行实体保持连续
4. 替换时把 span 的字符按 y 坐标聚成行组，每行一个矩形；
   首行写替换值，其余行涂黑

落盘：

- 首选：PyMuPDF `page.add_redact_annot(rect)` → `page.apply_redactions()`，
  它会真正删除文本层与裁剪图像
- 图像内的文字：`apply_redactions(images=PDF_REDACT_IMAGE_PIXELS)` 做像素级清除
- 兜底（无 PyMuPDF 时）：pypdfium2 渲染整页为图像 → 在图上打码 → 重建为纯图像 PDF
  （彻底没有文本层，最安全但不可搜索，许可证也更干净）
- **定位失败的安全网**：`search_for` / 投影都定位不到的文本，说明该页排版异形，
  此时对整页做栅格化（从原文件渲染 → 视觉+OCR 检出全部敏感区域 → 实心填充 →
  整页 redaction 清空 → 贴回打码后的位图）。宁可这一页不可搜索，也不留文本层残留。
- 元数据：清空 `/Info`（Author/Title/Subject/Keywords/Creator/Producer）与 XMP
- 附件与增量更新历史：PDF 的增量更新会把旧版本对象留在文件尾部，
  `apply_redactions` 后必须**重新保存为新文件**（`garbage=4, deflate=True, clean=True`），
  不能原地增量保存

### 6.3 XLSX

单元格值、共享字符串表 `sharedStrings.xml`（改了单元格但共享串没改会漏）、
公式 `f`（可能硬编码值）、批注 `comments*.xml`、
文档属性 `docProps/*`、定义名称、数据验证列表。
用 openpyxl 处理后**另存**，不保留原表。

### 6.4 图片

cv2 检测 → 矩形填充（不透明实心，不是半透明）→ 重新编码。
**必须清除 EXIF**（GPS 是重灾区，`PIL` 保存时不传 `exif` 参数）。

## 7. 残留自检（本工具的核心交付物）

脱敏完成不等于脱敏成功。产物必须被"反向攻击"一次。

流程：
1. **全量再提取**：把产物当陌生文件重新解包，抽出所有可读文本
   —— DOCX 遍历 zip 内每个 `.xml`/`.txt`/`.bin` 的原始字节流（不只是渲染文本），
   PDF 抽文本层 + 每页栅格化后 OCR，XLSX 同 DOCX。
2. **多粒度匹配**：对每个原始敏感值做
   - 全值匹配
   - 归一化匹配（去空格/全半角/繁简）
   - 子串匹配（长度 ≥4 的连续片段）
   - 结构残留（身份证后 6 位、手机号中间 4 位、银行卡后 4 位、姓名去姓）
3. **元数据检查**：产物所有 `docProps`/`/Info` 字段是否为空或已替换
4. **修订与批注检查**：产物内是否还存在 `w:ins`/`w:del`/`w:comment`
5. **视觉复检**（图片/扫描页）：产物图片再跑一次红章/QR/OCR 检测
6. **结论**：`PASS` / `FAIL` + 每条残留的部件路径、字节偏移、上下文片段

输出 `audit.json` + `audit.md` + `audit.html`（可点开看高亮上下文）。
FAIL 时进程返回非零码，可挂 CI。

## 7.5 验证方法与实测结果

自检说自己干净不算数。三条互相独立的验证路径：

### A. 端到端 + ground truth（`tests/e2e.py`）

样本由 `tests/make_samples.py` 生成，刻意把敏感信息埋进正文之外的地方：
页眉、页脚、批注（`comments.xml` + `people.xml`）、修订历史（`w:ins` / `w:del`）、
文档属性（author / lastModifiedBy / title / keywords / comments）、表格、内嵌红章图片。
所有证件号都通过真实校验位（GB 11643、GB 32100、Luhn），
保证检测器走完整判定路径而不是碰巧匹配。

| 样本 | 检出 | 召回 | 替换 | 自检 |
|---|---:|---:|---:|:--:|
| `当事人清单.txt` | 97 span | 37/37 | 76 | ✅ |

## 9. 已知局限（写清楚，别装）

1. **姓名召回有上限**。纯规则+词典对生僻姓、双字名、无角色词上下文的名字会漏。
   缓解：① 复核界面允许人工补标 ② 残留自检的子串匹配能抓到部分漏网
   ③ 留了语义 NER 插件位，可接本地 Qwen/HaS。
   做不到的是"闭眼全自动零漏"，任何声称做到的规则方案都在吹。
2. **准标识符组合重识别无法自动判定**。工具能泛化单个字段，但
   "1987年生+某村+独子+教师"这种组合是否可重识别，需要人判断。
   审计报告会给"高风险组合提示"，不替用户决策。
3. **手写体、模糊扫描件**的 OCR 召回取决于 RapidOCR 质量，低分辨率会漏。
4. **PDF 矢量图/流程图里的文字**（不是文本层而是绘图指令）可能扫不到，
   兜底方案是整页栅格化，代价是不可搜索。
5. **不处理音频视频**。
6. PyMuPDF 是 AGPL-3.0。自用无碍；若要分发，用 `--pdf-backend pypdfium2`
   走纯栅格化路径（Apache-2.0），代价是产物不可搜索。
